# 0.3.1 — 2026-10-08

## Added

- **`.env.example`** documents `MCP_REQUEST_STATE_KEY` (0.13.10), `LOG_TOOL_FAILURE_PAYLOADS` and `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` (0.13.8), the OTLP endpoint rows including logs (0.13.7, 0.13.8), and `LOG_LLM_INTERACTIONS` (0.13.13).

## Changed

- **Error results carry `data.requestId`** on tools, resources, and prompts, and a tool error's text ends `request <id>` (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)). Verified on this server's output.
- **Tool arguments are repaired before validation**: a numeric or boolean string for a number or boolean, a lone string for a list, and `null` at an optional key (treated as absent) (mcp-ts-core 0.13.14, [#707](https://github.com/cyanheads/mcp-ts-core/issues/707), [#602](https://github.com/cyanheads/mcp-ts-core/issues/602), [#616](https://github.com/cyanheads/mcp-ts-core/issues/616)). Verified here: `limit: "5"` on `cisa_search_kev` and `cisa_search_ics_advisories`, `cveIds: "CVE-2021-44228"` and `detail: null` on `cisa_check_cve_status`. Inputs that used to be rejected are accepted; nothing that used to succeed changes.
- **An ICS advisory index that cannot be opened** fails with `Failed to open mirror store "csaf.sqlite3".` (or `Failed to initialize …`), naming only the file, never its directory (mcp-ts-core 0.13.12, [#635](https://github.com/cyanheads/mcp-ts-core/issues/635)). The open waits out a held write lock up to its busy timeout before failing (mcp-ts-core 0.13.11, [#607](https://github.com/cyanheads/mcp-ts-core/issues/607)).
- **`ctx.log` messages reach the client only at or above `MCP_LOG_LEVEL`** (mcp-ts-core 0.13.11, [#621](https://github.com/cyanheads/mcp-ts-core/issues/621)).
- **With `OTEL_ENABLED=true`, `OTEL_EXPORTER_OTLP_ENDPOINT` alone exports traces and metrics**; a deployment with no endpoint set exports nothing (mcp-ts-core 0.13.7, [#523](https://github.com/cyanheads/mcp-ts-core/issues/523)).
- **On stdio, stdin EOF aborts requests still in flight**, unanswered (MCP SDK 2.1, via mcp-ts-core 0.13.9).
- **Explicit `ctx.recoveryFor` forwards removed** from the tools and services: the framework fills declared recovery hints on failures that carry a reason (mcp-ts-core 0.13.10, [#579](https://github.com/cyanheads/mcp-ts-core/issues/579)). The hint text callers see is unchanged.
- **Package description reads "STDIO or Streamable HTTP"** instead of "STDIO & Streamable HTTP" in `package.json`, `manifest.json`, both plugin manifests, the README, and the Docker image label; a process runs one transport at a time.
- **`server.json` npm entries** drop the `run start:*` arguments and use `runtimeHint: "npx"`; the HTTP entry sets `MCP_TRANSPORT_TYPE` to `http`, so a registry client starts it over HTTP (mcp-ts-core 0.13.11, [#622](https://github.com/cyanheads/mcp-ts-core/issues/622)).
- **Docker image** installs dependencies in a `deps` stage on the build platform, so multi-arch builds no longer run Bun under emulation (mcp-ts-core 0.13.10, [#575](https://github.com/cyanheads/mcp-ts-core/issues/575)), and prunes musl-only native packages from the glibc image (mcp-ts-core 0.13.11, [#608](https://github.com/cyanheads/mcp-ts-core/issues/608)).
- `package.json` `files` excludes `dist/*.mcpb` (0.13.8). `.gitignore` and `.dockerignore` ignore every `.env*` file except the templates (0.13.11); `.mcpbignore` adds `docs/idea.md`, `logs/`, `.cache/`, and `tests/`.
- `scripts/` resynced (devcheck, `lint:mcp`, `lint:packaging`, `check-skill-versions`, `check-framework-antipatterns`, `release:github`), with new `install-otel.ts` and `prune-musl-packages.ts`; `framework-skills/` resynced.
- `.github/workflows/codeql.yml` analyzes each language in its own matrix job under `/language:<language>`.
- `CLAUDE.md` and `AGENTS.md` track the framework and SDK versions and the request ID in error data; README badges updated.
