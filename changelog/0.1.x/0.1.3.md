# 0.1.3 — 2026-09-22

## Added

- **`cwe` filter** on `cisa_search_ics_advisories` — exact CWE membership via a new `advisory_cwes` junction table ([#10](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/10)).
- **`inKev` filter and `kevCves` output** on `cisa_search_ics_advisories` — narrows to advisories covering a KEV-listed CVE and reports which of each result's CVEs are in KEV, best-effort unless `inKev` is set ([#14](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/14)).
- **`cves` input** on `cisa_get_advisory` — narrows the `vulnerabilities` section to named CVEs; both outline arms now list the section's CVE IDs alongside its byte size ([#13](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/13)).

## Fixed

- **The 200-row product cap is gone.** Every flattened product row is now stored and indexed, so `cisa_search_ics_advisories` can match a product past row 200 and `cisa_get_advisory` with `sections: ["products"]` returns the whole list — 585 rows on the largest advisory ([#6](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/6)).
- **`q` with no searchable word or number** now throws `empty_search_text` instead of silently matching the whole corpus, and a punctuation-only token no longer produces a confident zero-hit result ([#7](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/7)).
- **`vendor` and `product`** filters escape `%` and `_` so they match literally instead of acting as `LIKE` wildcards ([#7](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/7)).
- **Sector extraction** resolves the short forms `Transportation`, `Water`, `Healthcare`, `Healthcare, Public Health`, and `Health, Public Health`, recovering 30 advisories a `sector` filter previously missed ([#8](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/8)).
