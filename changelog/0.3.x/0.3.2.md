# 0.3.2 — 2026-10-14

## Added

- **`cisa_get_advisory` `productIds`** selects exact, case-sensitive CSAF product IDs within `products`; alone it selects the products section, with `cves` it selects both, and explicit `sections` must include each selector's target. `productCount` and `vendorCount` stay whole-document totals, `shownProducts` counts returned definitions, and `products.selected` marks a selection. New errors `unknown_product_id` and `product_ids_need_products_section` ([#40](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/40)).
- **Product rows** carry `name`, `identificationHelper`, `relationshipCategory`, `productReference`, and `relatesToProductReference` where upstream supplies them ([#33](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/33)).
- **`cisa_get_alerts`** reports `fetchedAt` and `stale` on both surfaces ([#37](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/37)).
- **`cisa_list_reference` topic `sources`** reports `failedDocumentCount` and `lastSuccessfulCheckpoint` for the advisory index, and `syncStatus: "partial"` after a partial refresh ([#34](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/34)).
- **`mirror_busy`** (retryable `ServiceUnavailable`) on both ICS tools and the advisory resource for a transient `SQLITE_BUSY` or `SQLITE_LOCKED` index open, with topic `sources` reporting `syncStatus: "busy"` meanwhile; the advisory resource now declares its error contract, so a missing advisory carries `advisory_not_found` ([#28](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/28)).
- **`tsconfig.mirror.json`** resolves `@/` for the `mirror:*` scripts, shipped in the npm package, the `.mcpb` bundle, and the Docker image ([#30](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/30)).

## Changed

- **Advisory index content version 1 → 2**: an existing index re-ingests once on the next maintenance pass to pick up relationship and standalone product definitions ([#33](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/33)).
- **`cisa_get_alerts` refresh failure** serves the cached window with `stale: true` and retry guidance instead of silently; all attempts share a 45-second budget, and a stale empty result no longer reads as confirmed absence ([#37](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/37)).
- **A partial advisory refresh** keeps applied rows readable but leaves `lastCompletedAt`, `lastSuccessfulCheckpoint`, and the manifest ETag untouched, so the next refresh retries unresolved documents; `mirror:refresh` and `mirror:verify` exit non-zero ([#34](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/34)).
- **A first seed skipped under another process's lease** rechecks in the background (delay capped at five seconds) until the index is ready or the server closes; `CISA_CSAF_REFRESH_CRON=off` does not disable it, `CISA_CSAF_MIRROR_AUTO_INIT=false` does ([#39](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/39)).
- **Docker image** uses `oven/bun:1.4.3`; `packageManager` is `bun@1.4.3`.
- `bun run test:coverage` passes its global thresholds with new behavior tests, no threshold or exclusion changes ([#31](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/31)).
- `framework-skills/` resynced; `CLAUDE.md`, `AGENTS.md`, and the README track the framework, SDK, Zod, and Bun versions.

## Fixed

- **Impossible calendar dates are rejected** by `dateAddedFrom`, `dateAddedTo`, `dueBefore`, `dueAfter` on `cisa_search_kev`, `publishedFrom`, `publishedTo`, `revisedFrom`, `revisedTo` on `cisa_search_ics_advisories`, and `since` on `cisa_get_alerts`: month 00 or 13–99, day 00 or 32–99, day 31 in April, June, September, and November, February 30 and 31, and February 29 outside leap years. These were compared lexically and returned populated or empty results depending on the filter ([#38](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/38)).
- **`cisa_get_advisory` drops no relationship product**: definitions from branches, top-level `full_product_names`, and `relationships[].full_product_name` are all stored, searchable, and returned; IDs absent upstream are not invented (ICSA-23-227-01 returns `CSAFPID-0014` through `0017`) ([#33](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/33)).
- **Advisory Markdown shows upstream text literally**: `<LABEL>`-style placeholders, brackets, emphasis markers, and backticks no longer render as HTML or formatting; `structuredContent` is unchanged ([#36](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/36)).
- **A malformed KEV feed no longer yields false `inKev: false`**: a snapshot with a missing `vulnerabilities` array, unusable membership rows, duplicate normalized CVEs, or an inconsistent count is rejected whole, a cold read returns retryable `catalog_unavailable`, and a failed refresh keeps the last valid snapshot and its conditional-fetch state ([#35](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/35)).
- **A transient index lock** surfaces as retryable `mirror_busy` instead of an undeclared database error, and the next read succeeds once the lock clears ([#28](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/28)).
- **`mirror:refresh` on a never-completed index** exits non-zero with `mirror:init` guidance before any upstream request, and the `mirror:*` scripts resolve their imports from the npm package ([#30](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/30)).
- **stdin EOF during startup** no longer lets boot maintenance start a sync after shutdown or leave its lease behind; closing cancels pending boot work and releases only its own lease ([#39](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/39)).
