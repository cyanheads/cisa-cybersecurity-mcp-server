# 0.2.0 — 2026-09-25

## Added

- **`cisa_check_cve_status` takes `detail`**, `full` (default, unchanged) or `summary`. `summary` keeps the eleven triage fields per in-KEV record, cutting the 200 most recently added CVEs from 308 KB to 53 KB of `structuredContent`, and adds a `summaryNote` naming what it omits ([#9](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/9)).

## Changed

- **`nameContains` on `cisa_search_kev` with no letter a-z or digit 0-9 now fails `empty_search_text`** instead of returning zero results (breaking). `--`, `$$`, `——`, whitespace only, and `漏洞` are all rejected ([#16](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/16)).
- **The advertised `advisoryId` input pattern on `cisa_get_advisory` and `cisa://advisory/{advisoryId}` is now the canonical uppercase, flag-free one** (breaking). A client that validates arguments against `tools/list` before sending now rejects lowercase, `.json`-suffixed, or padded spellings; the server itself still normalizes them ([#20](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/20)).
- **`cwe` and `cveIdPrefix` on `cisa_search_kev`, and `cve` and `cwe` on `cisa_search_ics_advisories`, normalize case and surrounding whitespace**, so `" cwe-79 "` matches as `CWE-79` ([#17](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/17)). The advertised patterns are unchanged.

## Fixed

- **Every URL in a KEV entry's `notes` is now a `references[]` entry**, in notes order. Comma runs split, URLs inside prose are extracted, a `;` inside a URL no longer splits it, and trailing punctuation is trimmed; against catalog 2026.09.24, every entry now carries an `nvd` reference ([#15](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/15)).
- **The `cisa_search_kev` zero-hit notice names what actually excludes the results**: a filter that matches nothing on its own and what dropping it restores, or the filters whose removal restores results. It no longer blames `vendorProject`, `product`, or `cwe` when they match alone, and its figures come from the loaded snapshot and the echoed `asOf` ([#16](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/16)).
- **`nameContains` discloses a dropped word.** A word with a letter or digit outside a-z and 0-9, beside a surviving token, now raises a notice naming it and the tokens searched; results are unchanged ([#23](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/23)).
- **Tool, field, and `cisa_list_reference` `kev_fields` descriptions no longer state KEV catalog counts** that drift with each release ([#19](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/19)).
- **Advisory IDs with an uppercase revision suffix, such as `ICSA-10-316-01A`, validate against the advertised output schemas.** No advertised pattern carries the `/i` flag JSON Schema drops, so strict clients no longer reject a search page holding one ([#20](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/20)).
