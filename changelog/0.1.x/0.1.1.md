# 0.1.1 — 2026-09-19

First published release; `0.1.0` was the scaffold tag and never reached a registry.

## Added

- **`cisa_check_cve_status` and `cisa_search_kev`** — up to 200 CVE IDs per call against a cached KEV snapshot at zero upstream cost, plus filtered search over the whole snapshot by vendor, product, CWE, date added, due date, overdue, ransomware, forensic-triage tier, and directive. `directive` is three-state (`BOD 26-04` / `BOD 22-01` / `null`), never inferred from an entry's age.
- **`cisa_get_ssvc`** — CISA's published `exploitation`, `automatable`, and `technicalImpact` per CVE, plus the BOD 26-04 Table 1 timeline they imply for a caller-supplied `assetExposure`. The computed timeline and CISA's assigned KEV due date are reported side by side, never reconciled.
- **`cisa_search_ics_advisories` and `cisa_get_advisory`** — FTS5 search over advisory titles, vendors, and product names with vendor, product, CVE, CVSS, severity, sector, series, publisher, and date filters; a flattened advisory in seven addressable sections. Past a 24,000-byte budget the response is a section outline with per-section sizes instead of the record.
- **`cisa_get_alerts`** — the advisory, alert, or ICS feed's 30-item upstream window. `summary` is HTML-stripped and capped at 1,200 characters, with `summaryTruncated` flagging the cut.
- **`cisa_list_reference`** — BOD 26-04 Appendix A Table 1 as data, KEV field domains, SSVC values, the sixteen sectors, advisory ID formats, severity bands, and a `sources` topic reporting held state. Makes no network call, so it answers while another tool is failing.
- **`cisa://kev/{cveId}` and `cisa://advisory/{advisoryId}`** — resource twins of the KEV record and advisory payloads, with listing and argument completion.
- **ICS advisory index** — the CSAF corpus back to 2010 as embedded SQLite with FTS5 at `CISA_CSAF_MIRROR_PATH`, roughly 55 MB, seeded in the background on first run. Boot never waits on it: the KEV, SSVC, and alert tools serve from the first request while the ICS tools report a retryable `mirror_not_ready`.
- **`mirror:init`, `mirror:refresh`, `mirror:verify`** — out-of-band index lifecycle scripts, shipped in the npm package and the Docker image for `docker exec`, CI, and stdio deployments that cannot schedule a refresh.
- **Seven `CISA_*` variables** — `CISA_KEV_REFRESH_CRON`, `CISA_CSAF_MIRROR_PATH`, `CISA_CSAF_MIRROR_AUTO_INIT`, `CISA_CSAF_REFRESH_CRON`, `CISA_VULNRICHMENT_CACHE_TTL_SECONDS`, `CISA_FEED_CACHE_TTL_SECONDS`, `CISA_HTTP_TIMEOUT_MS`. Every one is optional: each source is keyless and each tunable has a working default.
- **Bounds on upstream input** — per-source body ceilings from 16 to 64 MiB counted as the bytes arrive, a 64 MiB tar-entry ceiling with chunked discard, `changes.csv` source-path validation before any fetch, a cisa.gov host check on an advisory's `self` reference, and a 512-character cap on search text.

## Fixed

- **`CveIdInputSchema` normalizes before the pattern check** ([#1](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/1)) — `" cve-2026-53266 "` now resolves as `CVE-2026-53266` on `cisa_check_cve_status`, `cisa_get_ssvc`, and `cisa://kev/{cveId}` instead of failing validation.
- **The advisory resource's outline notice names `cisa_get_advisory`** ([#2](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/2)) — a resource read has no `sections` parameter, so the notice routes to the tool by `advisoryId` with the smallest section as its example.
- **`cisa_list_reference` topic `sources` reports index state, not a filesystem path** ([#3](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/3)) — `ready`, `documentCount`, `syncStatus`, `checkpoint`, and `lastCompletedAt` answer the readiness question the path was carried for.

## Dependencies

- `better-sqlite3` `^13.0.3` — SQLite driver for the ICS advisory index under Node; Bun uses the built-in `bun:sqlite` and never loads it.
- `fast-xml-parser` `^5.11.1` — RSS parsing for the three publication feeds.
- `node-cron` `^4.6.0` — the KEV and advisory refresh schedules under HTTP transport.
