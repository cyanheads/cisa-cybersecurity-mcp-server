# 0.3.0 — 2026-09-25

## Added

- **`mirror_unavailable`** (`ConfigurationError`, non-retryable) on `cisa_search_ics_advisories`, `cisa_get_advisory`, and `cisa://advisory/{advisoryId}` when the index store cannot be opened; its recovery names `CISA_CSAF_MIRROR_PATH` and the tools that still work. `cisa_list_reference` topic `sources` reports `csafMirror.unavailableReason` without the path, and `resources/list` keeps listing the KEV entries ([#11](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/11)).
- **`cisa_get_advisory` misses carry `indexCheckpoint` and `indexLastSyncedAt`**, and the guidance says the advisory may be newer than the index when its ID's date is after the last sync. The `cisa://advisory/{advisoryId}` not-found carries the same ([#12](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/12)).
- **Cross-process sync lease on the advisory index.** Processes sharing one index never seed or refresh it at once; one that finds another syncing logs a skip and keeps serving reads. `mirror:init` and `mirror:refresh` take the same lease and exit 0 when skipped ([#12](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/12)).

## Changed

- **`CISA_KEV_REFRESH_CRON` and `CISA_CSAF_REFRESH_CRON` values that `node-cron` rejects** (`*/30 * *`, `none`, `disabled`) now fail startup with a `ConfigurationError` naming the variable (breaking); they used to log a warning on HTTP and were silently ignored on stdio. `off`, in any case, disables a schedule; empty still means the default ([#24](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/24)).
- **With `CISA_CSAF_MIRROR_PATH` unset, the index lives in the per-user cache directory** (breaking): `csaf.sqlite3` under `cisa-cybersecurity-mcp-server/` in `~/Library/Caches` (macOS), `$XDG_CACHE_HOME` or `~/.cache` (Linux), or `%LOCALAPPDATA%` (Windows). An index in `<cwd>/.mirror/` is no longer read and the new location seeds on first run; set the variable to keep the old path. The Docker image sets it to its `.mirror` volume, so container volumes are unaffected ([#11](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/11)).
- **`vendor` and `product` on `cisa_search_ics_advisories` are capped at 512 characters** (breaking); a longer value fails `search_text_too_long` ([#27](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/27)).
- **Stdio now runs the boot refresh and both refresh schedules** (breaking), so a stdio launch makes network requests at boot; it used to refresh only under HTTP. A synced index refreshes once at startup on every transport, and `CISA_CSAF_REFRESH_CRON=off` disables both that and the schedule ([#12](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/12)).
- **Toolchain:** Bun `1.4.0` → `1.4.2` (`packageManager`, Docker base images); `tsc` now typechecks the `scripts/` mirror scripts.

## Fixed

- **The `cisa_search_ics_advisories` zero-hit notice names what actually excludes the results**: a filter that matches nothing on its own and what dropping it restores, or the filters whose removal restores results. Its figures come from one aggregate query over the index, run only on a zero-hit result ([#21](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/21)).
- **ICS tool, field, and `cisa_list_reference` `sectors`, `advisory_id_formats`, and `severity_bands` text no longer states advisory-corpus counts.** `sectorCoverage` and `cvssCoverage` follow the index after every sync, thousands-grouped ([#22](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/22)).
- **`vendor` and `product` fold non-ASCII capitals on both sides**, so a label copied from a result, such as `GeutebrÃ¼ck`, matches its own advisories ([#27](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/27)).
- **`nameContains` on `cisa_search_kev` spells `ß`, `æ`, `ø`, `þ`, `ł` and the other Latin letters NFKD cannot decompose the CLDR Latin-ASCII way**, on query and record alike: `Straße` searches `strasse` instead of widening to `stra e` ([#25](https://github.com/cyanheads/cisa-cybersecurity-mcp-server/issues/25)).
